# Развёртывание на VPS

Рекомендуемый старт: Ubuntu 24.04 LTS, 4 vCPU, 8 ГБ RAM, 80 ГБ SSD/NVMe. Это оценка для пилота, не гарантия пропускной способности. Модель GPT-6 Luna вызывается по HTTPS, GPU не нужен. Для камеры в браузере обязателен HTTPS (кроме localhost).

## Подготовка

1. Установить Node.js 24 LTS из официального источника, pnpm 11.25.0, Git и Caddy. Проверить путь Node в unit-файле.
2. Создать системного пользователя `assistant` без интерактивного входа и каталог `/var/lib/company-assistant` с владельцем `assistant` и правами 700.
3. Клонировать `https://github.com/turn1k/company-assistant.git` в `/opt/company-assistant`. Приложение запускается ровно одним процессом: ограничение конкурентности использует память этого процесса. Не запускать несколько реплик / cluster без распределённой блокировки.
4. В корне проекта выполнить `pnpm install --frozen-lockfile --prod`.
5. Скопировать `deploy/server.env.example` в `/etc/company-assistant.env`, задать реальный домен, ключ OpenAI и часовой пояс. Права файла 600, владелец root. Не включать ключ в Git и команды shell с историей.
6. Создать первого администратора: `sudo -u assistant env DATA_DIR=/var/lib/company-assistant node /opt/company-assistant/scripts/create-admin.mjs`. Команда покажет одноразовый временный пароль. После первого входа его нужно заменить.
7. Установить unit из `company-assistant.service`, затем `systemctl daemon-reload` и `systemctl enable --now company-assistant`.
8. Направить DNS домена на VPS. Указать домен в Caddyfile, проверить конфигурацию `caddy validate`, перезагрузить Caddy. Открыть 80/443; доступ SSH ограничить согласно политике компании. Порт 3100 доступен только локально.

`TRUST_PROXY_LOOPBACK=true` допустимо только за доверенным прокси на loopback. Прямой внешний доступ к Node не предоставлять. Пример рассчитан на Caddy на том же сервере; при Docker/Cloudflare/другом прокси схему доверия требуется адаптировать, иначе IP будут определяться неверно.

## Проверка после запуска

- `/health` отвечает `{ "ok": true }`; вход администратора работает по HTTPS.
- Создать тестового сотрудника, сменить временный пароль, отправить короткий запрос в OpenAI и документ. Проверить usage и стоимость в кабинете провайдера.
- Проверить доступ к камере в браузере, Windows и macOS; запрет камеры должен оставлять возможность прикрепить файл.
- Проверить второй браузер/устройство в админ-панели, heartbeat, отзыв сеанса и блокировку.
- Перед использованием 20 сотрудниками провести тест с представительными PDF/XLSX: параллельная обработка тяжёлых документов расходует память. Настройка `MAX_CONCURRENT_REQUESTS` ограничивает нагрузку на весь сервер, стандартно 20.

## GeoIP

Для установки без аккаунта MaxMind используется DB-IP City Lite (CC BY 4.0, https://db-ip.com/db/download/ip-to-city-lite). Ссылка на источник отображается во вкладке «Подключения». Lookup выполняется локально, IP сотрудников не отправляются DB-IP. Настройки: `GEOIP_DATABASE=/var/lib/company-assistant-geoip/city.mmdb`, `GEOIP_PROVIDER=DB-IP`. База обновляется через `update-geoip.py` и unit/timer `company-assistant-geoip`: проверка новой месячной версии ежедневно, проверка формата до атомарной замены; при ошибке предыдущая база сохраняется. Каталог 755, MMDB 644. Сначала создать каталог и загрузить базу, затем включить env. Приложение следит за обновлениями; при недоступной базе вход продолжает работать без определения города. Восстановление VPS требует повторной загрузки GeoIP — база не входит в резервный архив.

Тип устройства и браузер определяются по User-Agent, без отпечатка оборудования. Браузеры могут скрывать модель или выдавать себя за другой клиент (например, iPad в режиме компьютера); точное число физических устройств и точную геопозицию эти данные не гарантируют.

## Мониторинг и Telegram

`monitor.py` запускается unit/timer `company-assistant-monitor` примерно раз в минуту независимо от Node-приложения. Проверяются systemd-сервис, HTTPS `/health`, резервная копия не старше 30 часов и результат последнего задания, свободное место не менее 10%, база GeoIP не старше 65 суток. Сбой подтверждается двумя проверками подряд; после восстановления приходит отдельное сообщение. Повторы текущего сбоя — не чаще 6 часов, неудачная доставка повторяется на следующей проверке. В сообщения не попадают запросы, вложения, IP сотрудников или токены.

Установить `monitor.py` в `/usr/local/sbin/company-assistant-monitor.py` (755), units в `/etc/systemd/system/`. Создать `/var/lib/company-assistant-monitor` с владельцем root:assistant и правами 750. Секреты — `/etc/company-assistant-monitor.env` (root:root 600): `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`; необязательный `MONITOR_URL=https://companyassistant.ru`. Адресат — только заранее выбранный личный чат владельца. Приложению задать `MONITOR_STATUS_FILE=/var/lib/company-assistant-monitor/status.json`; публичное состояние не содержит секретов и доступно только администраторам. `systemctl enable --now company-assistant-monitor.timer`, пробный запуск — `systemctl start company-assistant-monitor.service`.

Задание на самом VPS не обнаружит полное выключение VPS и не доставит Telegram при потере внешней сети. Для этого требуется независимый внешний мониторинг. Оно также не делает платных запросов к Ranvik и не проверяет баланс API. После восстановления из резервной копии токен Telegram надо задать заново: отдельный monitor.env не входит в архив приложения. Проверка алгоритма оповещений: `python3 deploy/test_monitor.py`.

Страна и город определяются опционально по локальной базе MaxMind GeoLite2 City (`GEOIP_DATABASE=/var/lib/company-assistant/GeoLite2-City.mmdb`). Базу предоставляет владелец сервера по условиям MaxMind, обновление нужно настроить отдельно. Без базы показываются IP и «GeoIP не подключён». VPN/прокси меняют географию. Приложение не собирает GPS и не отправляет IP внешнему сервису.

## Резервное копирование и обновление

### Автоматические копии без истории чата

`backup.py` делает согласованный снимок SQLite без остановки сервиса, удаляет из снимка тексты/ответы и сеансы, затем выполняет VACUUM. Вложения не копируются. В архив входят учётки (с хэшами паролей), лимиты, статистика, аудит и серверная конфигурация **с API-ключом**. Каталог `/var/backups/company-assistant` имеет права 700, архивы — 600; не публиковать и не помещать в Git. Хранятся 7 последних успешных копий. Каждая проверяется восстановлением базы во временный каталог, проверками integrity/foreign keys и отсутствия истории/сеансов.

Установка от root:

```sh
install -d -m 700 /var/backups/company-assistant
install -m 755 deploy/backup.py /usr/local/sbin/company-assistant-backup.py
install -m 644 deploy/company-assistant-backup.service deploy/company-assistant-backup.timer /etc/systemd/system/
systemctl daemon-reload
systemctl start company-assistant-backup.service
systemctl enable --now company-assistant-backup.timer
```

Расписание: 03:30–03:35 по Москве, пропущенный запуск выполняется после включения сервера. Проверка: `systemctl list-timers company-assistant-backup.timer`, `journalctl -u company-assistant-backup.service`. При ошибке не удаляются предыдущие копии. Уведомления об ошибках и внешнее хранилище пока отдельно не настроены; архивы на том же VPS не защищают от потери самого VPS.

Для восстановления сначала проверить архив: `python3 /usr/local/sbin/company-assistant-backup.py --verify /var/backups/company-assistant/ИМЯ.tar.gz`. Развернуть код по gitCommit из manifest.json и зависимости по lock-файлу. Остановить сервис, сохранить существующий каталог данных отдельно, восстановить `data/app.sqlite` в **пустой** `/var/lib/company-assistant`, создать пустую `uploads`, назначить владельца assistant и права каталога 700/базы 600. Проверить и восстановить env (root:root 600), unit и Caddyfile; не переносить SQLite WAL/SHM от старой базы. Выполнить daemon-reload, validate/reload Caddy, запустить сервис и проверить health и вход. Пользователи входят заново; последний запрос отсутствует. Никогда не распаковывать непроверенный архив поверх рабочей системы.

### Рублёвое отображение и лимиты

Для Ranvik используются `DISPLAY_CURRENCY=RUB` и фиксированный `ACCOUNTING_RUB_PER_USD`. Внутренние поля `usd`/`dailyUSD` оставлены для совместимости с существующей базой; интерфейс показывает расходы и принимает бюджеты в рублях. USD-тарифы в env должны быть равны рублёвым тарифам, делённым на этот коэффициент. Коэффициент после начала учёта **не менять** без миграции исторических расходов и лимитов. Это единица хранения, а не обновляемый биржевой курс. Суммы расчётные: скидки кэша и дополнительные платные инструменты не учитываются; точные списания — в Ranvik. При наших лимитах контекст ниже порога дорогого тарифа 272k.

Полный архив данных с историей чата по умолчанию не создаётся. Сроки хранения аудита и статистики следует согласовать отдельно.

Перед обновлением сделать резервную копию, остановить сервис, получить изменения Git, установить зависимости по lock-файлу, запустить сервис и выполнить проверку входа/запроса. Секреты остаются в `/etc/company-assistant.env`, данные — в `/var/lib/company-assistant`.

## Тарифы и ограничения

По умолчанию используется `gpt-6-luna`. Цены в env — стандартные цены за миллион токенов; меняя модель, обязательно изменить цены и подтвердить поддержку изображений. Скидки за cache hit не вычитаются: UI показывает расчётную стоимость. Неопределённый результат при timeout сохраняет максимальный резерв и отмечается в админ-панели.

Точный токенизатор текущей модели пока не интегрирован: приём текста использует консервативную оценку по UTF-8-байтам. Длинные документы могут отклоняться раньше лимита модели. Текст не обрезается. PDF без текстового слоя требуют отдельной загрузки страниц как фото; автоматического OCR всего PDF пока нет. XLSX читается как данные ячеек, без выполнения формул или макросов. Ответы можно экспортировать в TXT/Markdown и текстовые файлы TXT/MD/CSV/JSON, сформированные моделью; редактирование бинарных офисных документов пока не реализовано.
